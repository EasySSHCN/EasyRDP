## 二、同步语义说明

1. **仓库位置与副本策略**：数据目录（`%APPDATA%\EasyRDP`）下 `sync/` 子目录为独立 git 仓库（分支默认 `main`，仓库局部 user.name/email）。connections.json、groups.json、templates.json（**存在才同步**——F2-V2 的 templates.json 本次已并行落地，扩展点已生效）在每次落盘时原子写（临时文件+rename）副本进 sync/。
2. **凭据安全边界（严格执行）**：
   - 副本写入前，所有 `"dpapi:<base64 密文>"` 被替换为 `"dpapi:<不可迁移>"`（仅替换 JSON 字符串起始引号后的 dpapi: 值，普通文本中的 "dpapi:" 字样不受影响）——DPAPI 密文绑定本机用户，跨机器不可解，且进 git 等于泄漏高熵密文。
   - pull 恢复时占位符字段整段置空（`""`），**语义：恢复后的连接不带任何凭据，由用户在本机重新填写**。UI 安全说明中已明示。
   - 冲突时的远端备份 `*.remote.bak` 同样净化。
   - git 远端认证 token：settings.json 内恒为 DPAPI 密文；不回传前端；HTTPS 模式 push/fetch 时以 `https://x-access-token:<token>@host` 拼接（该 URL 存于 `sync/.git/config`，位于本机数据目录内——已知的 MVP 权衡，见遗留项）。
3. **commit**：有变更才提交（`git status --porcelain` 判空）；message 固定 `sync: <变更摘要> @ <UTC 时间>`，摘要形如 `新增 2，修改 1（连接）`。
4. **push**：每次幂等重设 origin（token 轮换即时生效）；SSH 模式经 `GIT_SSH_COMMAND` 注入 `-i <key>`；远端为空则跳过。
5. **pull 冲突策略**：比较远端 origin/<branch> 与本地 HEAD 的提交时间：
   - 远端较新 + 本地干净 → `reset --hard` 覆盖本地，UI 提示「已从远端恢复 N 条连接（凭据需重新填写）」并刷新列表；
   - 远端较新 + 本地有变更（冲突）→ **本地优先**，远端版本存 `<数据目录>/<文件名>.remote.bak`；
   - 本地领先 → 自动 commit + push；一致 → 无操作；远端为空 → 提示。

## 四、真机验证清单

1. 安装 git 并在 PATH：`git --version`；设置页状态区应显示「git 可用」。
2. 配置远端（HTTPS+token，如 GitHub/GitLab 私有空仓库）→ 保存 → 修改任一连接 → 确认 `%APPDATA%\EasyRDP\sync\` 自动创建、副本无明文无 dpapi 密文（`grep -r "dpapi:" sync/` 只命中占位符）、自动 commit + push 成功。
3. `git -C %APPDATA%\EasyRDP\sync log --oneline` 核对 message 格式 `sync: ... @ ... UTC`。
4. 第二台机器（或另一 Windows 用户）配置同一远端 → 「从远端拉取」→ 连接列表恢复 N 条、凭据字段为空、重填后可正常连接。
5. 冲突演练：两机各改一条连接后先后 push/pull，验证后拉方提示冲突、本地数据不变、生成 `connections.json.remote.bak`（内容已净化）。
6. SSH 模式：配置私钥路径 push/pull 各一次（含 `StrictHostKeyChecking=accept-new` 首次指纹写入）。
7. 自动提交粒度 = 仅手动：改连接后确认无自动 commit，「立即同步」按钮手动提交推送。
8. settings.json 中 `gitSyncToken` 为 `dpapi:` 密文；重新打开设置页 token 输入框为空且显示「已保存」；空值保存不清除旧 token。
9. templates.json（F2-V2）存在时随同步；`.remote.bak` / sync 目录不干扰连接中心正常读写。
10. git 未安装机器：设置页红色提示，push/pull 返回明确错误，应用其余功能不受影响。
