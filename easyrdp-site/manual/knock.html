端口敲门 （v0.5.0 新增 · 仅客户端）

服务器用 knockd / fwknop 做「端口敲门」防护时，3389 默认被防火墙关闭， 只有先发出正确敲门包 / SPA 包才会临时放行。EasyRDP 在连接前自动完成敲门， 无需手工敲完再连。服务器没开敲门时无需配置本区。

功能入口

「＋ 新建连接」或编辑已有连接 → 弹窗内展开「高级 / 端口敲门」折叠区。

参数说明

  • 连接前命令（钩子）：RDP 连接前执行的本机命令（如 rasdial MyVPN 先拨 VPN）。超时 15 秒、退出码非 0 即中止连接并提示；命令原样执行，不做拼接。
  • 启用端口敲门：勾选后 RDP 连接前先敲门，未通过即中止并提示分类原因（敲门未通过 / 密钥无效 / 服务不可达）。
  • 敲门类型 · 序列敲门（knockd）：
    • 敲门端口序列：按发送顺序填端口，如 7000,8000,9000（注意与 knockd.conf 中 sequence 的「敲开顺序」相反——conf 里最后一个端口在这里最后发，可直接用导入功能自动还原）；
    • 序列协议：UDP 包（0~8 字节随机负载）或 TCP SYN 即断；
    • 序列总时限 / 相邻包间隔：对应 knockd.conf 的 seq_timeout 与发包节奏，默认 10 秒 / 150ms。
  • 敲门类型 · 单包授权 SPA（fwknop）：
    • SPA 端口（UDP）：fwknopd 监听端口，默认 62201（对应 --udp-server -p）；
    • 开门有效期 fwTimeout：放行规则保持秒数，默认 30；
    • SPA 加密密钥 / HMAC 密钥：fwknop 原生裸密钥语义——服务器 access.conf 的 KEY / HMAC_KEY 填什么明文，这里就填同一明文；「随机生成」产出 32 字节 CSPRNG 密钥，保存后本机加密存储、不回显明文。SPA 包由 fwknop 官方 libfko 库构造（Rijndael-256 + HMAC-SHA256），与原生 fwknopd 逐字节互通。
  • 开门端口：敲门成功后要放行的端口，默认 tcp/3389，多个逗号分隔（对应 fwknop OPEN_PORTS）。
  • 从 knockd.conf 导入：把服务器 /etc/knockd.conf 内容粘贴进来点「解析并填充」，sequence 倒序还原发送顺序、seq_timeout 自动带入。
小贴士：敲门结果与失败原因会写入客户端 debug 日志（含真实 ws/wss scheme 的回环桥日志同管线）；连接重试不会重复敲门（短时间去重窗口）。SPA 密钥与网关凭据一样受 DPAPI（Windows）/ 密钥文件 + AES-256-GCM（Linux）保护，模板库发布与导出时自动剥离。

典型用法（fwknop 为例）

  1. 服务器确认 fwknopd --udp-server -p 62201 运行中，access.conf 配好 KEY / HMAC_KEY 与 OPEN_PORTS tcp/3389；
  2. 新建连接填好主机 / 端口 / 凭据；
  3. 展开「高级 / 端口敲门」→ 勾选「启用端口敲门」，类型选「单包授权 SPA」；
  4. SPA 端口填 62201，密钥粘贴 / 随机生成后同步写入服务器 access.conf；
  5. 点连接：客户端先发 SPA 包 → 防火墙临时放行 3389 → RDP 直连目标机；
  6. 若提示「敲门未通过 / 密钥无效 / 服务不可达」，按分类核对端口、密钥与 fwknopd 状态。
