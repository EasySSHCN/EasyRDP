Quick Start

1. Grab the installer for your platform from the Download page and verify it with the SHA256 checksum as instructed.
2. Windows build currently available: unzip and run directly (macOS / Linux builds are planned).
3. After launching, complete three steps in "New Connection": ① enter host, port (default 3389), username and password → ② click "Save" to store the connection in the Connection Center → ③ click "Test Connection" to run a TCP handshake, confirm the host is reachable and view the latency.
4. Already have mstsc .rdp files? Click the file selector (system file open dialog) during import to pick a .rdp file — fields are mapped automatically to a JSON Profile, no manual entry needed.
5. Press Ctrl+K to open the global search and switch between hosts at lightning speed.

Windows requires the WebView2 Runtime (usually preinstalled on Win10/11); if missing, the app will offer to install it automatically at runtime.

JSON Profile

Each connection corresponds to a JSON Profile, stored in the user configuration directory and ready for Git version control. Core fields: 

{
  // Connection name (unique identifier, basis for Ctrl+K search)
  "name": "office-win11",
  "host": "192.168.1.100",
  "port": 3389,

  // Auth method: "password" | "nla" | "gateway-otp" (gateway on the roadmap)
  "auth": {
    "type": "password",
    "username": "administrator",
    "store": "os-keychain"   // credentials go into the OS keychain, never plaintext
  },

  // Redirection switches
  "redirection": {
    "clipboard": true,
    "drive":   true,
    "printer": false,
    "usb":     false,
    "audio":   true
  },

  // Optional: session appearance
  "session": {
    "resolution": "1920x1080",
    "multiMonitor": false,
    "colorDepth": 32
  },

  // Optional: gateway access (V1 roadmap field, reserved)
  "gateway": null
}
Note on credential storage: in v0.3.4, passwords are only stored in the local user configuration directory (plaintext for now, never uploaded to any server); upcoming versions will switch to encrypted storage in the OS credential store (DPAPI / Keychain / libsecret), with only an encrypted entry reference kept in the Profile. See the FAQ.

.rdp Import

EasyRDP is compatible with standard .rdp files generated by mstsc. Two ways to import:

  • GUI: in "New Connection / Import", click the file selector (system file open dialog) and pick a .rdp file; fields map automatically to an EasyRDP JSON Profile.
  • Command line: linkdesk import office.rdp (see CLI below).

Supported field mappings (excerpt):

.rdp fieldJSON Profile fieldDescription
full address:shost + porthost:port split automatically; default port 3389
username:sauth.usernameUsername; passwords are not migrated from .rdp files
desktopwidth / desktopheightsession.resolutionInitial resolution
redirectclipboard:iredirection.clipboardClipboard redirection
drivestoredirect:sredirection.driveDrive redirection
redirectprinters:iredirection.printerPrinter redirection
The encrypted password 51:b: block in .rdp files is only valid on the local Windows machine. EasyRDP does not import the password at import time; re-enter it when connecting or save it to the OS credential store.

CLI Usage

EasyRDP ships with a command-line tool, linkdesk, for scripting and CI scenarios:

# Connect: by Profile name or host
linkdesk connect office-win11
linkdesk connect 192.168.1.100 --port 3389 -u administrator

# Import: convert mstsc .rdp files into JSON Profiles
linkdesk import office.rdp
linkdesk import ./*.rdp --overwrite

# Other common commands
linkdesk list            # list all Profiles
linkdesk export office-win11 -o office-win11.rdp   # export as .rdp
linkdesk --version       # show version
On headless (no-desktop) environments the CLI provides Profile management only; establishing graphical sessions still requires a local GUI environment (WebView component dependent).
