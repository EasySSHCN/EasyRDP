v0.3.3

2026-11-17

Clipboard completion release: text clipboard protocol fix + bidirectional file clipboard transfer.

Fixed

  • Local copy could not be pasted into the remote desktop (text direction, R-20261117-011): the client's clipboard announcement arrived before Monitor Ready — a protocol ordering violation that strict servers silently drop. Now the announcement waits until the Monitor Ready/Capabilities exchange completes (cached for retransmission when not ready). Additionally: if MonitorReady is not received within 10s of connecting, a hint appears at the bottom — "Remote clipboard service is not ready (rdpclip not responding)" — guiding the user to restart remote rdpclip

Added

  • Bidirectional file clipboard transfer (R-20261117-011): implements the standard CLIPRDR FileContents protocol — after copying files locally, a FileGroupDescriptorW + FileContents named format is announced to the remote side; when pasting remotely, the server responds to FileContentsRequest with descriptors and content chunks (1 MiB disk reads). In the reverse direction, files copied on the remote side are automatically downloaded to "Downloads\EasyRDP-Clipboard\" and placed on the local clipboard. Enables the streaming file capability bit (paths never leave the wire); signature-based deduplication prevents loops; ≤128 files per transfer, ≤2 GiB per file

v0.2.2

2026-11-16

Ghosting root-fix release: incremental blit pipeline disabled by default, full-frame presentation path + stale backing-store channel fix.

Fixed

  • Block ghosting root fix: incremental blit pipeline disabled by default (GHOSTFIX4-R023): the carrier of block ghosting in the five scenarios (load / button hover / window drag / icon drag / click) was the incremental pipeline itself (tiles extracted pixel-by-pixel from the composition buffer → merged in 16 ms batches → blitted back to frame storage by the presentation layer); the multi-level timing gaps could not be sealed one by one. Now only the "EndPaint gating + full-frame dual checksum snapshot" full-frame path is used by default (torn frames are discarded and never emitted), structurally eliminating the old tile-blit-back channel. Incremental mode must now be explicitly enabled via EASYRDP_ENABLE_DELTAS=1 (for experimental comparison), with one final gate added at the end of the emit thread
  • Stale backing-store channel fix in the presentation layer (GHOSTFIX5-R023): frame-storage writes and window backing-store updates were non-atomic; during the gap, WM_PAINT could blit the stale backing store, presenting an entire old frame. Introduced frame-generation counters (FRAME_GEN/BACKING_GEN); when the backing generation lags the frame generation, blitting the backing store is forbidden and the direct-paint branch is taken
  • Chained regression from first-paint suppression and guarded emission reverts (GHOSTFIX2-R023 rollback): the previously introduced "emit only when first-paint coverage ≥80%" gate froze the picture on stale content during load and risked deadlock in full-frame mode; it has been reverted in full

Verified

  • End-to-end audit (present-audit): in full-frame mode, pump delta=0 and the engine emits only full-frame snapshots; frame-by-frame sampling inspection across load / welcome screen / desktop shows no black base, no tile grid, and no stale content bleed-in

v0.2.1

2026-11-16

Ghosting-focused fix release: root-cause fix for the presentation-layer Delta/full-frame timing inversion; ghosting sealed in the load / window-drag / button-hover scenarios.

Fixed

  • Remote desktop ghosting root fix (presentation-layer Delta/full-frame timing inversion): stale incremental batches expiring after a full frame arrived wrote old pixels back into frame storage and repainted dirty rectangles, causing old-frame flashbacks. Fixed by flushing pending incremental batches before presenting the full frame, restoring strict event ordering and structurally eliminating three scenarios: flicker ghosting during load, edge ghosting when dragging software windows, and hover ghosting on title-bar minimize/maximize/close buttons (real-machine traffic replay: previously 8 ghost frames / 650k stale pixels per incident → zero after the fix on that path)
  • Hardened engine snapshot consistency verification: sparse sampling upgraded to full-frame dual checksums (any single-byte write is captured); emit-thread snapshots are deferred during EndPaint batch processing, closing the residual tearing window where the order path wrote the framebuffer directly
  • 1px under-coverage fix for incremental dirty rectangles: stale pixel columns at the right/bottom edges under non-integer scaling factors; dirty rectangles now use edge-point rounding and are clamped to the window bounds
  • Fixed two PowerShell console windows flashing at startup: the shortcut-refresh child process now includes CREATE_NO_WINDOW

v0.1.3

2026-11-16 2026-11-16

Remote desktop ghosting root-fix release: the true cause was located as server-side bitmap cache reference desynchronization (not the presentation layer); disabling bitmap cache negotiation eradicates grid tiling and text-overlay flashbacks.

Fixed

  • Remote desktop ghosting root fix (TILEGHOST): during batched image changes — load / mouse click / IME candidate window / window drag / app launch — the whole screen showed a 64×64 grid tiling ghost and the login screen's old text overlaid on top. Bitmap cache negotiation (BitmapCache/V3) is disabled so the server sends raw bitmap data directly, fixing the problem at its source. Cost: slightly higher bandwidth; picture correctness takes priority.

v0.1.0 (Stable)

2026-11-15 2026-11-15

EasyRDP's first stable release. Portable, no installation: double-click to run (a single fully static-linked Windows file, no DLLs required). This release lands the full remote desktop core experience: native FreeRDP session window, direct mouse/keyboard input pass-through, bidirectional clipboard sync, incremental frame pipeline with ghosting root fixes, remote cursor shape sync, and Win key & Ctrl+Alt+Del (SAS) support.

Added

  • Native FreeRDP session window (Windows): an independent top-level window with a custom-drawn title bar (minimize/maximize/close/drag), full-frame direct painting via StretchDIBits, with zero encoding and zero IPC overhead.
  • Input pass-through: full forwarding of mouse (move / left-middle-right buttons / wheel / horizontal wheel) and all keyboard keys; the Win key is intercepted via a low-level keyboard hook and forwarded (remote Start menu works normally).
  • Ctrl+Alt+Del delivered to the remote side: via the title-bar SAS button or the local Ctrl+Alt+End hotkey (extended scancode sequence, SAS synthesized server-side).
  • Bidirectional clipboard sync (CLIPRDR CF_UNICODETEXT): local copy → remote paste, remote copy → local paste, with loop protection.
  • Incremental frame pipeline: dirty-rectangle incremental painting + EndPaint full frames (33 ms throttling ~30 FPS during motion + 5s fallback + pending retransmission), with adaptive load shedding during motion.
  • Remote cursor shape sync (monochrome/color/32bpp alpha anti-aliased); keyboard LED (NumLock/CapsLock) sync.
  • Disaster-recovery package mechanism: source code + build components + recovery docs packaged in one click, allowing full restoration of development/build capability on another machine.

Fixed

  • Drag ghosting (root fix): full-frame snapshots now read the GDI primary buffer — previously, order updates (window dragging) never entered the composition buffer, freezing ghost frames in place.
  • Input failure root cause: fixed a defect in the window-procedure message arming (degenerate WM_NCCREATE/WM_DESTROY binding swallowed all messages).
  • Main UI restoration and process exit after closing a window; black-block ghosting on move/resize; black square cursor; first-packet disconnect after ACTIVE; 1-2 FPS stutter during dragging — all fixed.

  • JSON Profile: connection configs described as JSON, with import / export and versioned management.
  • .rdp compatibility: import .rdp files generated by mstsc, and export back to .rdp.
  • Remote sessions: basic RDP sessions on the FreeRDP protocol stack, with clipboard and drive-redirection toggles.
  • Secure credential storage: Windows DPAPI / macOS Keychain / Linux libsecret.
  • Cross-platform builds: Windows x64 zip, macOS dmg, and Linux AppImage artifacts.
  • Initial CLI: linkdesk connect and linkdesk import.

Changed

  • Tech stack settled: Rust + Tauri 2 + FreeRDP protocol stack + WebView2 (Windows).
  • TLS policy: enforce TLS 1.2 and above; reject weak cipher suites.
  • Build security: CFG (Control Flow Guard) and ASLR compile-time mitigations enabled.

Fixed

  • Initial release; no historical bug-fix records.
  • Known limitations: installers are not yet code-signed; multi-monitor switching may show resolution flicker under certain drivers (to be fixed in a later version).
