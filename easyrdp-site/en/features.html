Features

Six feature domains cover the full range of personal and enterprise remote desktop scenarios: F1–F4 and the F5 lite console have shipped (see the roadmap below); the full F5 console and F4 wss/OIDC enhancements are scheduled for later releases.

🗂

F1 · Connection Center

The Connection Center is EasyRDP's main interface: every remote host is presented as a card, sortable and groupable by name / tag / recently used; each remote session runs in its own tab, so parallel sessions never interfere with one another; the global Ctrl+K search pinpoints the target connection among hundreds of hosts in an instant, with fuzzy matching across hostnames, notes, and tags.

  • Card-based connection management: grouping, favorites, pinning; connections support save / edit / delete
  • Tabbed multi-session: parallel sessions + quick switching
  • Ctrl+K global search: fuzzy matching on hostname / notes / tags
  • Importing mstsc .rdp files supports the native file picker dialog — select and import in one step
  • Connectivity check: TCP handshake + latency display, verifying host reachability before you connect
  • Passwords are stored locally only — never uploaded to any server
📄

F2 · New Connection & .rdp Compatibility

The new connection wizard covers host, port, credentials, resolution, and redirection options; it is also fully compatible with .rdp files generated by mstsc — drag one in to import it, with fields automatically mapped to EasyRDP's JSON profile, and you can export existing connections back to .rdp for use with the built-in Windows client. Zero migration cost.

  • New connection wizard: host / port / authentication / redirection in one pass
  • Import mstsc .rdp files (full address, username, redirect* fields, and more)
  • Export standard .rdp — fully interoperable in both directions with the system Remote Desktop client
🖥

F3 · Remote Sessions

The session layer is built on the FreeRDP stack: RDP 8+ remote compression, adaptive resolution, and multi-monitor support, plus clipboard / drive / printer redirection. Reconnect quickly after a drop to resume your session, and image quality degrades automatically during network jitter to keep things smooth.

  • Multi-monitor and adaptive resolution
  • Clipboard / drive / printer redirection toggles
  • Automatic reconnection after disconnects and adaptive image quality
🛡

F4 · Gateway Access Roadmap · V1

A self-hosted cloud gateway for complex enterprise networks: the client only makes outbound access to the gateway on port 443, and RDP traffic is forwarded internally through a TLS tunnel; access requires pre-authentication first, followed by a one-time OTP code as a second verification factor — no need to expose port 3389 of any internal host.

  • TLS tunnel over port 443 (reusing the HTTPS channel)
  • Pre-authentication + OTP second-factor verification
  • Gateway-side host mapping with least-privilege access
  • Resource registry / bidirectional tunnel forwarding (in development)
🏢

F5 · Admin Console Roadmap · V2

The administrator console: integrates with SSO / OIDC for unified identity authentication with enforced MFA policies; a policy matrix governs device redirection (clipboard / drives / USB / printers) at fine granularity; session watermarking, on-demand recording, and complete audit logs meet compliance requirements such as MLPS and internal controls.

  • SSO / OIDC + MFA unified authentication
  • Device redirection policy matrix (per user / host / time window)
  • Session watermarking, recording, and audit logs
🧩

F6 · Configuration as Code

Every connection is a JSON profile that can be kept in Git and code-reviewed; teams can share profile templates for bulk rollout; compatible with importing mstsc .rdp files and exporting back to .rdp, seamlessly bridging legacy tooling and infrastructure-as-code (IaC) workflows.

  • JSON profiles: structured, versionable, template-ready
  • .rdp two-way import / export compatibility
  • CLI support: linkdesk connect / linkdesk import
