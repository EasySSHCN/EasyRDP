Frequently Asked Questions

High-frequency questions about installation, compatibility, the gateway, and security policy. For anything not covered here, please open a GitHub Issue.

Windows shows "Unknown publisher / SmartScreen blocked" on first run — is it safe?

The v0.3.4 installer has not yet purchased a code-signing certificate, so Windows SmartScreen shows a warning (the macOS build is planned; once released, Gatekeeper behaves the same way). First verify the SHA256 checksum as described on the Download page, confirm it matches, then choose "Run anyway". Stable releases will ship signed installers and an auto-update channel.

How do I import mstsc .rdp files?

Two ways: ① drag a .rdp file directly into the Connection Center window; ② run linkdesk import office.rdp on the command line. Fields are mapped automatically (full address → host:port, redirectclipboard → clipboard switch, etc.). See the Docs for details. Note: the encrypted password block in a .rdp file cannot be migrated across machines — re-enter the password after import and save it to the OS credential store.

Does EasyRDP depend on FreeRDP? Do I need to install it separately?

FreeRDP is required, but no separate installation is needed: EasyRDP bundles the FreeRDP protocol stack via static linking / in-package distribution, working out of the box. FreeRDP itself is open source under Apache-2.0, and EasyRDP's modifications to it are likewise published in the source repository.

How is the cloud gateway (443 TLS tunnel) deployed? Is it usable now?

The gateway is part of the V1 roadmap and is not included in v0.3.4. Planned design: the gateway runs as a standalone service in the enterprise DMZ or on your own cloud, with clients making outbound-only connections to the gateway on port 443 (the TLS tunnel reuses the HTTPS channel). Access requires pre-authentication plus OTP two-factor verification, and internal hosts' port 3389 stays fully unexposed. Helm / Docker deployment options and configuration docs will be provided at that time.

How do I enable session watermarking / recording / audit policy?

These capabilities belong to the admin console (V2 roadmap): administrators push a policy matrix per user / host / time window from the console — watermarks (username + timestamp), on-demand recording, and audit log policies. Client sessions fetch and enforce them automatically at startup, and end users cannot turn them off. At the v0.3.4 stage you can manually enable simple watermarking for a single connection in its JSON Profile (for testing purposes).

Where are passwords stored? Could plaintext ever leak?

In v0.3.4, passwords are stored only locally in the user configuration directory, in plaintext for now, and are never uploaded to any server; upcoming versions will migrate to OS-level credential stores (Windows DPAPI, macOS Keychain, Linux libsecret) for encrypted storage, with only an entry reference kept in the Profile JSON. The Changelog will record this migration. The transport layer enforces TLS 1.2+ and prefers NLA (Network Level Authentication).

What does the Connect button error / "engine not connected" message mean?

The graphics engine is still being integrated in v0.3.4: the current version already implements the Connection Center (save / edit / delete connections), .rdp import, and TCP connectivity testing (handshake + latency display), but the FreeRDP graphics session engine is not yet wired in. So clicking "Connect" shows the "engine not connected" message — this is expected behavior, not an indication of a misconfigured host. Use "Test Connection" to verify host reachability for now; graphics session capability will arrive in a later release.

How are passwords stored? Is it secure?

In v0.3.4, after checking "Remember password", credentials are stored only locally (in the user configuration directory) and are never uploaded to any server. They are currently stored as plaintext in a local file — please make sure your user account is protected by a login password. Upcoming versions will switch to OS-level encrypted storage: DPAPI on Windows, Keychain on macOS, libsecret on Linux, with only an encrypted entry reference kept in the Profile JSON. The Security Policy page will track this change as well.

Which Windows / remote host versions are supported?

Supported: Windows 7 SP1 and above with Remote Desktop enabled (Win10/11 recommended), Windows Server 2008 R2 and above; also compatible with third-party RDP implementations (e.g. xrdp, Windows 365 Cloud PC). macOS / Linux hosts need an RDP-compatible server running.

The connection is laggy / the screen is garbled — what should I do?

Troubleshoot in order: ① check your bandwidth (≥ 5 Mbps recommended); ② lower color depth (16-bit) or resolution in connection settings; ③ confirm the host has RDP 8+ remote compression enabled; ④ disabling unused drive / printer redirection significantly speeds up first connections; ⑤ if the problem persists, submit FreeRDP logs to GitHub Issues (debug output can be enabled in Settings).
