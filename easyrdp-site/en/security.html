Security Policy

We take the security of EasyRDP and its users very seriously. If you discover a vulnerability, please report it privately through the channels on this page — never disclose it publicly.

🔒 Vulnerability Reporting

If you discover a security vulnerability (credential leakage, protocol implementation flaws, memory safety issues, supply-chain risks, etc.), please email:

security@easyrdp.cn (placeholder mailbox; before it goes live, the repository's SECURITY.md is authoritative)

You can also submit directly from within the app: feedback submitted through the "Feedback" button in the EasyRDP client title bar also reaches the development team (content is transmitted encrypted). If email is inconvenient for you, you may report security issues through this channel — please start your feedback with [Security Vulnerability] and include reproduction steps and an impact assessment; for sensitive details (e.g. PoCs, evidence of credential leakage), prefer the email channel and avoid public disclosure over unencrypted channels. Submitted feedback is uploaded via an encrypted envelope, and IPs are stored only as hashes; nothing is displayed publicly.

Please try to include in your report:

  • Vulnerability type and impact assessment (remotely exploitable? affected versions)
  • Detailed reproduction steps or a PoC
  • Affected platform (Windows / macOS / Linux) and version numbers
Response commitment: we will acknowledge receipt of your report within 3 business days and provide an assessment and remediation plan within 30 days. Until the fix is released, please do not disclose details publicly. We will credit reporters in security advisories (anonymity on request).

🛡 Security Baseline

AreaMeasure
Transport encryptionTLS 1.2+ enforced, weak cipher suites disabled; NLA (Network Level Authentication) preferred
Credential storageEncrypted storage via Windows DPAPI; no plaintext in Profiles (macOS Keychain / Linux libsecret planned)
Compile-time mitigationsCFG (Control Flow Guard), ASLR (Address Space Layout Randomization), and DEP enabled
Data collectionNo telemetry, no tracking; the only network activity is the RDP session itself
Supply chainReleases ship with a SHA256 checksum file; dependencies locked and CI builds reproducible
