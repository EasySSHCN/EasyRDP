Migration Guide

Move from mstsc / Remmina / Royal TS / Sunlogin · ToDesk to EasyRDP · importing a .rdp file carries your connection setup over, and passwords always stay on your machine only

Migration Overview

EasyRDP is built on Rust + Tauri 2 + FreeRDP and imports the standard .rdp files generated by mstsc (Windows' built-in Remote Desktop Connection) out of the box. It can also export existing connections back to .rdp for full two-way interop with the Windows built-in client. Combined with JSON Profile import/export, tabbed parallel sessions and bidirectional clipboard sync (text + files), most migration scenarios require no manual re-entry at all.

After import, each connection is a JSON Profile (stored in the local user config directory, so it can be versioned in Git), and Ctrl+K global search lets you switch between hosts at lightning speed. Enter the password once on first connection; to move connections in bulk, use JSON Profile import/export.

1. Importing .rdp Files (Session / Connection Setup Migration)

If you have been connecting to servers or colleagues' machines with mstsc, most of those connections are probably already saved as .rdp files (use "Save As" in mstsc to create one; they default to your Documents folder). EasyRDP offers three ways to import them:

Method A: Import via the GUI (recommended)

  1. Open the import entry point: launch EasyRDP and click the file picker (system file dialog) in the "New Connection / Import" panel.
  2. Select the .rdp files: pick the .rdp files exported from mstsc (you can select multiple and import them one by one).
  3. Confirm the field mapping: on import, fields are mapped automatically into EasyRDP's JSON Profile (see the mapping table below) — no manual input needed.
  4. Add the credentials: enter the password when you first connect to that host and you're ready to go.

Method B: Drag into the connection hub

Drag the .rdp file straight into the connection hub window and the import is done — fields are mapped automatically, exactly equivalent to Method A.

Method C: Bulk import from the command line (linkdesk CLI)

# Single-file import: turn an mstsc .rdp file into a JSON Profile
linkdesk import office.rdp

# Bulk import every .rdp file in the current directory (--overwrite replaces same-name Profiles)
linkdesk import ./*.rdp --overwrite

# Export back to .rdp for use with the Windows built-in client
linkdesk export office-win11 -o office-win11.rdp

🟢 Two-way interop: importing is only the first step in one direction — EasyRDP can also export existing connections as standard .rdp files, so you can swap freely with colleagues who still use mstsc at zero cost.
⚠️ The password 51:b: encrypted block in a .rdp file is only valid on the Windows machine that generated it (DPAPI-bound). EasyRDP does not import the password on import; you re-enter it at connection time.

2. Credentials and Security Notes

  • Passwords stay on your machine, never uploaded: in v0.3.4 passwords are saved only in the local user config directory and are never sent to any server; future versions will switch to system credential storage (DPAPI / Keychain / libsecret) with the Profile keeping only an encrypted reference (see the FAQ).
  • JSON Profile import/export: every connection is a JSON Profile — field-based, versionable, ready for Git and code review; teams can share Profile templates and roll them out in bulk, making "configuration as code" real. Spec: Docs · JSON Profile.
  • Never bring plaintext config into a public repository: Profiles currently store credential-related fields (the username) in plaintext, while passwords stay on your machine only per the rules above. Before syncing the config directory to a cloud drive / private Git repo, make sure it contains nothing sensitive.
  • Portable, registry-free: EasyRDP is a single-file portable build — no registry writes, no drivers, no resident server-side components. Delete the file and it is fully uninstalled, keeping the machine clean before and after migration.
  • Verify your download: get installers from the download page and compare hashes using the SHA256 verification instructions before running them.
💡 For users migrating from mstsc: mstsc's default "Allow me to save credentials" hands your password to Windows Credential Manager. EasyRDP stores credentials in its own location that can be audited alongside Profiles — after switching, clean up the old system-saved credentials as needed.

4. Notes on Migrating from Other RDP Tools

  • Fully static FreeRDP linking — no server-side components to install: EasyRDP's Windows single-file build is fully statically linked (no DLL dependencies); just double-click to run. Nothing — services, drivers, resident components — is installed on the client side, and uninstalling means deleting the folder.
  • Only the WebView2 Runtime is required (usually preinstalled on Win10/11; if missing, the runtime offers to install it automatically).
  • Protocol capabilities come from standard RDP: RDP 8+ compression, multi-monitor, clipboard and drive/printer redirection are all provided by the FreeRDP stack — connecting to the same target machine as mstsc requires no extra server-side configuration.
  • Test connectivity before connecting: v0.3.4 supports a pre-connection TCP reachability test (one click checks host reachability and port response and shows latency). When migrating your first batch of hosts, test them one by one to quickly catch mistyped addresses or ports.
  • Migrating from Sunlogin / ToDesk: China remote-control tools use proprietary protocols and are not bound by Windows Remote Desktop rules. Once you switch to EasyRDP you use standard RDP, so confirm the target machine has "Remote Desktop" enabled (Settings → Remote Desktop), the account has remote logon rights, and the firewall allows port 3389.
  • Gateway access (planned): the JSON Profile already reserves a gateway field; the cloud gateway and policy matrix (fine-grained control of clipboard/drive/USB/printer redirection) are on the roadmap for future releases — see the Features page.

5. Migration FAQ

Q1: Why am I asked to re-enter the password after importing a .rdp file?

The password 51:b: encrypted block inside a .rdp file is only valid on the Windows machine that generated it (DPAPI-bound). EasyRDP never imports the password and never migrates or uploads any password. Enter it once on first connection; it stays on your machine only.

Q2: The imported connection fails — how do I troubleshoot?

First run "Test Connection" on it for a TCP handshake: if it fails, the address/port is probably wrong, Remote Desktop isn't enabled on the target, or the firewall isn't allowing port 3389; if it succeeds but the session misbehaves, check whether the account has remote logon rights. You can also cross-check the imported field-mapping table to confirm the host:port split is correct.

Q3: Are there limits on file clipboard transfers?

≤128 files per transfer and ≤2GiB per file; directories are conveyed as empty-directory placeholders. Transfers use the standard CLIPRDR FileContents protocol and move only descriptors and content streams (paths never leave the wire). Remote→local files land automatically in "Downloads\EasyRDP-Clipboard\".

Q4: Pasting a file does nothing?

The remote session's rdpclip clipboard service may have stalled — every client fails in that state. EasyRDP shows a bottom-bar notice "remote clipboard service not ready (rdpclip not responding)" when no clipboard-ready signal arrives within 10 seconds of connecting; follow the prompt to restart the remote rdpclip.

Q5: Can EasyRDP always reach hosts that Sunlogin / ToDesk can?

Not necessarily. China remote-control tools don't rely on Windows Remote Desktop, while EasyRDP uses standard RDP: the target machine must have Remote Desktop enabled and port 3389 open. Home editions of Windows typically allow only a single concurrent session, and if the account isn't in the local Administrators group it must first be added to "Remote Desktop Users".

Q6: How do I move all my connections to another computer?

Use JSON Profile import/export: Profiles are plain JSON files, so you can copy the config directory directly or sync it via Git; for bulk scenarios, script the move with linkdesk import / export. See Docs · CLI Usage.
