# EasyRDP 方案：用户反馈提交 + 后台管理回复审核 + 前台展示 + 需求池联动

> 版本：v1.0（2026-11-16）｜状态：**待用户审批**（批准后才实施开发）
> 对标：EasySSH v5.1.x 已上线反馈机制（feedback.rs / ui/js/feedback.js / api/feedback/* / admin.html / harvest-feedback.ps1 / AI 复审定时任务）

## 一、总体架构（四层闭环）

```
软件端(客户端)                网站端(easyrdp.cn)              后台管理                需求池联动
反馈弹窗(类型/联系方式/内容)  → api/feedback/submit.php       → admin.html 反馈页签   → harvest 定时采集入池
  + 系统信息静默采集              (信封解密/IP哈希/频控/落库)     (登录→列表→回复→        → AI 复审定时任务
  + AES-256-GCM 信封加密                                          公开/删除,完整分页)      (real/spam/reject)
  → POST 提交                 → api/feedback/top.php          → admin.php 管理接口    → apply-review.ps1
                              (前台只读已回复+公开的 TOP10)       (会话/验证码/防爆破)     (回写池+官网状态)
```

## 二、软件端（easyrdp-client）

### 2.1 UI（src/index.html + src/ui/main.js + style.css）
- 工具栏新增「反馈」按钮 → 反馈弹窗：
  - 类型下拉：功能建议 / 问题反馈 / 其他
  - 联系方式（选填，≤120 字符）
  - 内容 textarea：5–2000 字，附「计算字数」按钮（与 EasySSH 相同的提交口径 trim 后校验，实时提示差多少字/超多少字）
  - 提交按钮（防重复点击）+ 结果提示
- 弹窗加官网入口链接（easyrdp.cn/download.html）

### 2.2 后端（src-tauri/src/feedback.rs，新增模块 + main.rs 注册命令）
- 静默采集系统信息随信封加密上报（≤24 项，键≤24 字符、值≤300 字符）：应用版本、OS 版本、CPU/内存、屏幕分辨率、系统区域等；**不采集任何明文 IP/主机名/用户名**（服务端只存 IP 哈希）
- 信封加密（与 EasySSH 同协议族，master 密钥不同）：`{v:1, alg:"A256GCM-HS256", ts, nonce, ct, tag, mac}`；encKey/macKey = HMAC-SHA256 派生自 master（Rust 侧 aes-gcm + hmac + sha2 crate，均在现有依赖族内）；ts 时效 ±15 分钟防重放
- API：`https://easyrdp.cn/api/feedback/submit.php`（与在线升级检测同族协议，复用派生方式）

## 三、网站端（easyrdp-site/api/feedback/，新增）

四个 PHP 文件 + 密钥文件，逻辑对标 EasySSH 并做 EasyRDP 特化：

| 文件 | 职责 |
|---|---|
| `common.php` | 信封解密校验（mac→时效→GCM 解密）、JSON 文件库原子读写（数据目录放 **webroot 外** `<站点根上级>/data/`）、IP 归属（仅信任 keys.php 声明的可信代理，存 sha256 哈希不存明文）、频控（同 IP 每小时 5 条 + 间隔 60 秒）、管理员会话（可吊销随机 token 12h）、登录失败限速（15 分钟 5 次锁定）、图形验证码、邮件通道 |
| `keys.php` | PHP 退出守卫（首行 `<?php exit(0); ?>`）+ JSON：master 密钥、admin_user/admin_hash、token_secret、trusted_proxies、mail 通道。**敏感文件：只在服务器存在，不入仓库/发布包（脱敏门禁覆盖）** |
| `submit.php` | 仅 POST：解密 → 类型白名单（功能建议/问题反馈/其他）→ 内容 5–2000 字校验 → 频控 → 入库 `{id, ts, date, ipHash, appVersion, type, contact, content, reply:'', replyAt:0, public:false, status:'new', systemInfo}` |
| `admin.php` | 动作：login（图形验证码+限速+bcrypt）/ list / add / edit / delete / **reply**（写回复、置 replied）/ **setpublic**（是否公开前台） |
| `top.php` | 公开 GET：返回**已回复且公开**的反馈最新 10 条（id/type/date/content 截 300 字/reply/replyAt），不含联系方式与系统信息 |

> 前置验证项：easyrdp.cn 服务器 PHP 可用性（宝塔 webroot 结构，实施第一步实测 `php -v` + 试部署探针页）。

## 四、后台管理（easyrdp.cn/admin.html，新增统一后台 + 反馈页签）

- 新建 `admin.html` 统一后台（EasyRDP 目前无后台页）：管理员登录（用户名+密码+图形验证码）、找回密码（绑定邮箱验证码）、修改密码、登录态 12 小时
- 「反馈管理」页签：
  - 列表：按时间倒序，类型/状态筛选，显示类型、日期、版本、内容、联系方式、回复、公开状态
  - 操作：**回复**（1–2000 字）、**公开/取消公开**（公开前台 TOP10）、删除、手动补录
  - **完整分页**（遵守 DSH 级永久规范：区间信息+首页/上一页/页码折叠/下一页/末页+每页 10/20/50/100 条记忆；直接移植 easyssh admin.html 的 `fullPager()` 通用函数）
  - 展示侧全部 HTML 转义防 XSS；每次操作后刷新列表

## 五、前台展示（easyrdp.cn/download.html，新增板块）

- download.html 新增「用户之声 · 反馈精选」板块：读 `api/feedback/top.php` 渲染最新 10 条公开已回复反馈（用户内容 + 官方回复成对展示，官方回复醒目样式）
- 只读公开接口，不暴露联系方式/系统信息；内容转义防 XSS

## 六、需求池联动（与已落地的需求池机制闭环）

1. **采集脚本** `scripts/harvest-feedback.ps1`（新增）：每日 08:00/20:00 由系统任务调用——SSH 到 easyrdp.cn 服务器拉取 `data/feedback-db.json` → 垃圾启发式过滤（单字符连跑/复读/测试占位/低信息熵，同 EasySSH 规则）→ 新反馈分析后登记入池（status=记录，source=官网反馈，sourceRef=反馈 id）→ 写 `reqpool/review-queue.json` 待审队列 → 官网自动回复"已收录"并公开 TOP10
2. **AI 复审定时任务**（DSH schedule，新增「EasyRDP 反馈内容 AI 复审」）：读待审队列 → 逐条真实意图分析（real/spam/reject + 理由）→ 写 verdicts → 调 `scripts/apply-review.ps1`（新增，对标 EasySSH）：real=入池公开 / spam=移除下架 / reject=回复说明并下架
3. real 条目进入需求池正常计数 → 满 3 条触发发布周期（复用已落地的 release-check/pool-add 机制）

## 七、安全设计要点（本次不做附件上传）

- 传输：AES-256-GCM 加密信封 + HMAC 完整性 + 时间窗防重放（EasySSH 的 R-20261115-005 附件上传功能尚在安全方案审批中，EasyRDP 首版**不做附件**，规避该风险面）
- 存储：数据目录 webroot 外；IP 仅哈希；keys.php 退出守卫 + 脱敏门禁
- 展示：前后台全部 HTML 转义；top.php 不回传联系方式/systemInfo
- 防滥用：双端频控；登录图形验证码 + IP+用户名失败锁定；管理会话可吊销

## 九、验收标准

- 软件端提交一条反馈 → 后台可见（含系统信息）→ 回复并标记公开 → 前台 TOP10 出现该条（内容+回复成对）→ 取消公开立即消失
- 频控生效（第 6 条/分钟内被拒）；伪造信封被拒；明文 IP 不落库
- 采集脚本把新反馈入池并在待审队列出现；AI 复审 real 条目保留、spam 条目下架
- 完整分页规范达标；php -l 全过；401/405/429 错误码正确
