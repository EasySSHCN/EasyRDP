# SPA 密钥语义变更说明（R-20261122-SPA，已开发未发布）

## 背景

EasyRDP 客户端的 fwknop SPA 敲门原为自研实现（`SHA256(key)` 派生 AES-256-CBC、
自定义明文字段、`port,proto` 消息格式），与原生 fwknop 2.6.10 **不互通**
（fwknopd 预检即丢弃；详见 spa-interop 对照实验 emit2/3/4.py 的逐层证明）。

本次改造用 **fwknop 官方 C 库 libfko 2.6.10**（vendor 于
`easyrdp-client/crates/easyrdp-core/vendor/libfko-2.6.10/`，经 build.rs + cc
直接编入二进制）替换全部自研加解密，Rust 侧仅保留最小 FFI
（`src/fko.rs`）。SPA 包与原生 fwknopd **逐字节互通**。

## 密钥语义变化（重要）

| 项 | 旧自研实现 | 新实现（fwknop 原生） |
|---|---|---|
| 加密密钥 key | `SHA256(字符串)` 派生 AES-256 密钥 | 字符串**裸密钥**（libfko 内部 PBKDF2 派生 Rijndael-256） |
| HMAC 密钥 hmacKey | `SHA256(字符串)`（实际 hmac 覆盖 b64 密文） | 字符串裸密钥（HMAC-SHA256，覆盖 b64 密文，同 fwknop） |
| 线格式 | `b64(iv+AES密文):b64(HMAC)`（含 `:`） | `b64(iv+Rijndael密文)` 直接拼接 `b64(HMAC)`（**无 `:`、无 `=` 填充**） |
| 访问消息 | `ip,port,proto` | `ip,proto/port`（fwknop 语义） |

**后果**：升级后，旧自研格式下保存的 SPA 密钥**失效**，必须按 fwknop
`--key-gen` / access.conf 语义重新生成：

* 服务器 access.conf 用 `KEY:` / `HMAC_KEY:` 时，EasyRDP 填同一**明文字符串**；
* 服务器用 `KEY_BASE64:` / `HMAC_KEY_BASE64:` 时，EasyRDP 填 base64 解码后的
  原始字节对应的字符串（或直接用同一 base64 串取决于两端约定——推荐统一用
  明文 `KEY:` 形态，两端逐字符一致即可互通）。

与 `fwknop` CLI 的对应关系：EasyRDP 的 key/hmacKey 等价于
`fwknop --key <KEY> --hmac-key <HMAC_KEY> --use-hmac`。

## 改动文件

* 新增 `crates/easyrdp-core/src/fko.rs`：libfko 最小 FFI
  （fko_new / fko_set_spa_message / fko_set_spa_hmac_type /
  fko_spa_data_final / fko_destroy）。
* 重写 `crates/easyrdp-core/src/knock.rs`：`build_spa_packet` 走 libfko；
  删除纯 Rust AES-256/CBC/HMAC 自实现与旧格式解密回读（死代码一并移除，
  FIPS 向量测试随之删除——本地 AES 不再使用）。
* 新增 `build.rs` + `Cargo.toml [build-dependencies] cc`：vendor libfko 编译。
* 新增 `examples/spa_send.rs`：真机互通回归入口（发 UDP / 写包文件两模式）。
* vendor 目录（来源 fwknop 2.6.10 官方源码，与 Debian bookworm fwknop
  2.6.10-3 同源；WSL /tmp/fwknop-2.6.10 复用）：lib/ + common/(fko_util,
  strlcpy, strlcat) + getlogin + 手写双平台 config.h。MSVC 兼容最小补丁
  （均在 vendor 内注释标记 "EasyRDP vendor patch"）：
  1. fko_common.h：去掉 `_snprintf` 别名与手工 uint typedef（现代 MSVC 有
     C99 snprintf 与 stdint.h）；
  2. cipher_funcs.h：gpgme_funcs.h include 按 HAVE_LIBGPGME 条件化（客户端
     构建无 gpgme）；
  3. cipher_funcs.c：WIN32 随机数种子加进程内调用计数（原实现同毫秒两次
     调用产生相同 IV/salt）。

## 真机互通回归结论（2026-11-22，WSL2 Ubuntu-22.04，fwknopd 2.6.10）

`fwknopd --udp-server -p 62201 -f -v`，access.conf 明文
`KEY: interop-key-2026` / `HMAC_KEY: interop-hmac-2026` / `OPEN_PORTS: tcp/3389`。
EasyRDP `examples/spa_send`（生产同一 libfko 路径）发包：

* 正向：`SPA Packet from IP: 127.0.0.1 received with access source match` →
  `Message Type: 1 (Access msg)` / `Digest Type: 3 (SHA256)` /
  `HMAC Type: 3 (SHA256)` → `SPA Data Digest: pjhIvz6Gq8dpY89Vy+zxrvauDadmhDiyxz5jxyI2rZ4`
  → HMAC 通过 → **`Added access rule to FWKNOP_INPUT for 127.0.0.1 -> tcp/3389`**，
  `iptables -L FWKNOP_INPUT` 出现 `ACCEPT tcp dpt:3389` 带过期注释。
* 负向（错误 HMAC）：`FKO_ERROR_INVALID_DATA_HMAC_COMPAREFAIL`，拒绝，无规则添加。
* 测后 `pkill fwknopd` 清理。

## 构建注意（MSVC D8050）

本仓库默认 target 目录路径较长，`cc` 生成 cl.exe 调用会触发
`D8050 无法将命令行放入调试记录中`（c1.dll debug record 路径长度限制）。
构建/回归请用短 target 目录，例如：
`set CARGO_TARGET_DIR=C:\er-target && cargo test`。
