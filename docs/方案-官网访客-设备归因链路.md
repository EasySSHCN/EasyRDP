# 方案与交付报告：官网访客-设备归因链路（R-20261118-001）

> 日期：2026-11-18 · 状态：已实现（代码落库，随 v0.3.4 客户端+官网一起发布生效）

## 一、目标

把官网「访客」（visit-db 流水）与客户端「设备」（client-db 遥测）匿名关联起来：
下载 → 安装 → 客户端首报时携带下载票据 → 服务端建立弱归因 → admin.html
「已产生设备的访客记录」（visit.php `produced` 动作）出现数据。

归因是「匿名访问 ↔ 匿名设备」的弱关联，不含任何个人身份信息（对齐 EasySSH 同族实现）。

## 三、链路时序

```
浏览器                      官网 PHP                          客户端(Rust)
  │ 点击下载按钮                │                                │
  │ POST api/download/ticket.php│                                │
  │───────────────────────────▶│ 频控(30/h/IP)                    │
  │                            │ 查 visit-db: 同完整IP±10min 流水 │
  │                            │ 签发 ticket_id, flock 落盘       │
  │◀───────────────────────────│ {ok, ticket_id}                 │
  │ localStorage 记票           │                                │
  │ GET downloads/xxx.exe?t=…   │ (下载行为照旧)                   │
  │                            │                                │ 安装/首启动
  │                            │                                │ 读 exe同目录 ticket.id
  │                            │◀── POST api/stats/client.php ──│ {action:report, anonId,
  │                            │   fields白名单+按日频控          │  ticket_id?, fields}
  │                            │ 票据在窗内 → 设备档案写 origin   │
  │                            │ 票据.attributed += anonId       │
  │                            │                                │
  管理后台：visit.php produced/detail 读 origin.visitId → devices 反向标注生效
            admin.html「已产生设备的访客记录」/ 设备明细 origin.via=ticket 展示
```

兜底语义：超窗未消费的票据不归因；无票据设备（GitHub 直下/老包/降级直下）只产生匿名
遥测，不进归因链路；绿色版多设备共用一张票上限 10 台。

## 四、安装包 ticket 注入点设计（打包侧，本轮未改打包脚本）

目标：用户拿到的 exe/zip 内含与本次下载对应的 ticket.id，客户端首启动即可归因。

推荐主方案（URL 参数 + 打包时注入，与现有便携包结构最贴合）：

1. **签发即绑定**：download.html 前端已把下载 URL 改为
   `downloads/EasyRDP-x.y.z-portable.exe?t=<ticket_id>`。静态文件服务器忽略 `?t`，
   下载行为与字节完全不变，浏览器下载的 URL 查询参数保存在下载记录里。
2. **安装器注入（官方安装器场景）**：打包/分发脚本增加一步「按票重打包」接口
   （服务器端 CGI/CLI，后续实现）：
   - 输入 `?t=<ticket_id>` → 校验票据存在 → 复制通用 exe 模板 → 在 exe 末尾追加
     自定义段或在同目录生成 `ticket.id`（内容 = ticket_id）→ zip 重打包后以
     `EasyRDP-x.y.z-<ticket_id>.exe` 签名/命名下发。
   - 客户端 `telemetry.rs` 已支持两条读取路径，任选其一即可：
     a) **exe 同目录 `ticket.id` 文件**（本版已实现）：绿色 zip 安装时解压脚本/用户
        手动放置均生效；MSI/NSIS 安装器在安装目录写入 `ticket.id` 一行文本。
     b) exe 末尾追加段（`ticket=<ticket_id>` 尾部标记，后续版本可加 4 字节长度前缀
        扫描），对用户完全无感，但需签名排序注意（签名后不可再改文件，需先注入后签名）。
3. **注册表方案（MSI 安装器备选）**：安装器写
   `HKCU\Software\EasyRDP\Attribution\ticket_id`（REG_SZ）；后续版本 telemetry 读
   注册表兜底（当前版本未读注册表，读取顺序建议：exe 目录 ticket.id → 注册表）。
4. **直接下载 / 降级直下**：无注入机会，票据仅留在浏览器 localStorage 与服务端，
   客户端走纯匿名遥测——链路自然降级，不影响统计。

隐私注记：ticket_id 为纯随机数，文件内不含任何用户信息；用户删掉 ticket.id 即断开关联。

## 六、遗留事项（随 v0.3.4 发布清单）

1. 客户端：telemetry 首报生效需 v0.3.4 客户端发布后才有设备数据；v0.3.3 及更早版本不上报。
2. 打包侧：按票重打包/安装器 ticket.id 注入（见 §4）尚未实现，本轮交付仅含注入点设计；
   实现前 v0.3.4 安装包可先手工放置 ticket.id 验证链路。
3. 服务端：需在服务器创建数据目录 `/www/wwwroot/easyrdp-data/tickets/`（与 stats 目录同
   属主/权限，02775；首次调用若目录缺失 st_locked_update 会自动 mkdir，但建议预建）。
4. 验证脚本建议（部署后）：
   `curl -X POST https://easyrdp.cn/api/download/ticket.php` → 得 ticket_id →
   `POST api/stats/client.php {action:"report",anonId:<32hex>,ticket_id:...}` →
   admin 后台「已产生设备的访客记录」/ 设备明细 origin 显示 via=ticket。
5. telemetry 当前未读注册表（§4.3 备选）；如 MSI 安装器落地，v0.3.5 可加注册表兜底读取。
6. 频控口径：客户端按日 1 次（本地时钟）；服务端保留既有同 IP 30 次/小时滑动窗频控，
   时钟被改的用户最多多耗几次服务端额度，无滥用放大面。
