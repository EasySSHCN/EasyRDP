# EasyRDP

Windows 开源远程桌面客户端 · Rust + Tauri 2 + FreeRDP · MIT 协议（macOS / Linux 支持规划中）

**官方网站：https://EasyRDP.CN** · [GitHub](https://github.com/EasySSHCN/EasyRDP) · [Gitee](https://gitee.com/easyssh/EasyRDP)

## 目录结构

| 目录 | 说明 |
|---|---|
| `easyrdp-client/` | 跨平台客户端（Rust workspace：easyrdp-core + src-tauri 壳） |
| `easyrdp-gateway/` | 云网关服务（axum + tokio：认证/隧道/审计/策略） |
| `easyrdp-site/` | 官网静态站（已部署 https://easyrdp.cn ） |
| `docs/` | 产品 PRD 与架构文档 |

## 快速开始

```bash
# 客户端（需 Rust stable 工具链）
cd easyrdp-client
cargo test -p easyrdp-core     # 核心库单元测试
cargo tauri dev                # 桌面端调试运行

# 网关
cd easyrdp-gateway
cargo test                     # 8 个单元测试
cargo run                      # 默认监听 0.0.0.0:8443
```

### v0.2.2（2026-11-16）

残影根治版本（需求池 R-20261116-023/024/025/026 四条触发）。

#### Fixed 修复

- **方块残影根治：增量贴图管线默认停用（GHOSTFIX4-R023）**：载入/按钮悬停/窗口拖动/图标拖动/点击五场景方块残影的载体是增量管线本身（tile 从合成缓冲逐包抠像素 → 16ms 合并批 → 呈现层贴回帧存储），多级时序缝隙无法逐一封堵。现默认只走「EndPaint 门控 + 整帧双路校验和快照」全帧通路（撕裂即丢弃不发射），结构上不存在旧 tile 贴回通道；增量模式改为 EASYRDP_ENABLE_DELTAS=1 显式启用（实验对照用），发射线程终点再加最后一道闸门（任何来源 Delta 任务直接丢弃）
- **呈现层陈旧背板通道修复（GHOSTFIX5-R023）**：帧存储写入与窗口背板更新非原子，间隙内 WM_PAINT 会 blit 旧背板呈现整幅旧画面（拖边缩放时边缘旧画面块闪现同源）。引入帧世代计数（FRAME_GEN/BACKING_GEN），背板世代落后于帧世代时禁止 blit 背板、直绘画帧分支
- **撤销首刷抑制与守卫撤销的连锁回归（GHOSTFIX2-R023 回收）**：此前引入的「首刷覆盖率 ≥80% 才发射」闸门造成载入期画面冻结在旧内容、且在全帧模式下有死锁风险（needs_full 无人清除），已整体撤销

#### Verified 验证

- 端到端审计（present-audit）：全帧模式下 pump delta=0、引擎仅发整帧快照；载入/欢迎屏/桌面各阶段抽帧目检无黑基底、无 tile 网格、无旧内容混入

残影专项修复版本（需求池 R-20261116-015/018/019/020/021/022 六条触发）。

#### Fixed 修复
